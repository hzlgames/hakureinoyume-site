# 0008 使用独立后台进程和 PostgreSQL 保存共享直播字幕

## Status

Proposed — 已在审核分支实现，尚未合并或部署。

## Context

多个已授权用户观看同一智云课节时，逐用户识别会重复拉流和支付 ASR 费用。识别不能随网页刷新丢失，也不能因 Next.js 重启而让内存中的任务状态永久滞留。学校的转录接口在本次直播实测返回无语音数据。

## Decision

以租户、课程、课节和教室音源为共享身份，使用独立 systemd 后台服务执行音频处理。PostgreSQL 保存字幕和分片时间锚点，并用事务锁、租约和 generation 限制重复工作及旧进程写入。用户拥有独立访问记录和观看心跳；共享文本不扩大上游课节访问权限。文本保存七天，不保存完整音视频。

HLS.js 教室画面根据媒体分片对应字幕；其他画面和原生 HLS 没有可靠时间映射时明确显示为实时转写。使用浏览器 TextTrack，而不在服务器重新编码视频。

## Consequences

同一课节的识别费用与观看人数分离。需要配置额外后台服务、密钥、预算和清理定时器。按需启动和无人停止无法保证整节课完整转录；网络故障或直播窗口滑出可能造成缺口。数据库历史恢复和整节课云端稳定性需分别验证。
