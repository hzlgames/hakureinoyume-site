# 网易云播放器排查记录

本次修复在 `codex/netease-player-fix` 验收分支进行。状态控制器、认证与曲库请求已分开，生产发布须在预览验收后进行。

## 已确认根因与处理

| 场景 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 不同歌单/账号收到同一份结果，二维码状态迟迟不变 | 上游两分钟缓存只按 URL 与 HTTP Cookie 区分；本站 POST 请求体中的参数、账号 Cookie、时间戳未参与缓存键 | 统一调用加入 `x-apicache-bypass` 与带时间戳和随机请求 ID 的 URL，防止不同查询/账号甚至同毫秒调用碰撞；详情响应再次校验 ID |
| 获取音源时点击暂停，随后又开始播放 | 自动播放标记没有被暂停操作撤销 | 控制器独立保存播放意图，音源返回后再次判断 |
| 连点下一首跳错曲目 | React 闭包内的队列索引落后于点击 | 选曲同步写入控制器，旧请求与旧媒体实例失效 |
| 同一地址或单曲循环不重新开始 | 仅依赖 URL 变化触发加载 | 每次选曲建立新的媒体实例 |
| 音频加载失败后按钮状态错误 | 未处理媒体 error/waiting 或过期链接 | 显示缓冲/失败状态，显式重试会重新获取链接 |
| 操作系统暂停后按钮仍显示暂停 | 原生暂停只修改视觉状态 | 同步媒体暂停与播放意图，忽略过时的暂停事件 |
| 浏览新专辑/歌单后下一首跳入新列表 | 读取曲目同时覆盖播放队列 | 只有选曲/播放全部更新队列，提供独立队列入口 |
| 搜索类型切换时结果回跳 | 搜索回调依赖类型，导致初始化 effect 重跑 | 初始化稳定，搜索有取消与请求代次，旧响应不切页 |
| 专辑缺封面、歌手头像成为专辑图 | 错误 fallback，缺少元数据补全与加载错误处理 | 歌曲详情补全正确封面；HTTP 网易云 CDN 转 HTTPS；失败用图标 |
| 游客或过期账号显示已连接 | 只看顶层 code，兜底旧 profile | 识别嵌套状态、游客 account/profile；未知状态保留账号并提示验证受阻 |
| 上游 HTTP 401 无法触发前端重连 | HTTP 异常丢失业务码 | 保留统一登录失效错误；旧凭据请求不能使新凭据过期 |
| 偶发风控被当作登出 | `-462` 与包含“登录”的任意文案被判失效 | 风控明确提示官方验证，不销毁账号状态 |
| QR 过期不刷新、一断网就永久停止 | 过期/错误分支终止定时器，没有恢复路径 | 800 自动换码，网络故障退避重试，轮询不重叠 |
| 刷新/关闭二维码后旧请求覆盖新二维码 | 没有整次登录流程的失效边界 | 每次刷新/关闭递增代次并取消请求、清理定时器 |
| 扫码 Cookie 带属性、登录确认不完整 | Set-Cookie 直接拼接，未验证有效账号 | 清除 Path/Expires 等属性，只在凭据与资料有效时绑定 |
| 站内退出/跨标签登录后私人列表残留 | 仅挂载时读一次账号，登出未清空喜欢列表 | 监听站内身份、可见性、联网与跨标签事件；私人请求随账号代次失效 |
| 网页歌单乱序或旧响应覆盖新操作 | 多个增删排序并发写回完整列表 | 客户端写入互斥；账号变化后丢弃旧结果；排序增加键盘/触控按钮 |
| 静音后无法恢复、暗色按钮看不清 | 零音量取消静音仍为零、按钮未指定主题颜色 | 恢复非零音量，保存音量偏好，控件使用主题文字色 |
| 异常响应被显示为没有搜索结果 | 非 JSON/空响应被接受为成功 | 明确报告上游故障，游客凭据失效后有限重试 |

## 验证边界

- 26 项音乐单元测试通过；另 3 项既有 ZJU 登录测试通过。控制器与协议/服务测试覆盖取消、乱序、媒体事件、队列、重试、Cookie、登录状态与二维码票据绑定/篡改/过期。额外为现有 ZJU 登录测试补了 `this` 类型注解，以消除全量类型检查中已有的错误；运行行为不变。
- 13 组浏览器场景通过。回归在真实 Chromium 媒体元素上使用本地 WAV 和可控接口响应，覆盖播放/暂停、延迟返回、连点切歌、搜索竞态、专辑返回、二维码 800/802/803 与 503 恢复、跨标签状态、网页歌单排序和简易模式持久化。
- 视觉矩阵包含 320/390/1280px、浅色/深色、简易/详细模式；检查页面溢出、可聚焦区域与浏览器错误。
- 真实游客请求已验证：搜索可返回带专辑封面的曲目；歌曲 `687111` 的地址响应为 MP3、完整曲目、有效期 1200 秒，实际 Range 读取返回 `206 audio/mpeg`。这些是测试时观测值，音源可用性受网易云当前授权与地区约束。
- 用户已在隔离数据库对应的站内测试会话中亲自扫码，真实检查返回 803，随后 `/me`、`/playlists`、`/likes` 均返回 200；读到 2 个歌单、3 首喜欢的歌曲。
- 真实账号揭示了上游缓存串数据：请求 82 首的第二个歌单，原实现返回另一个 3 首歌单的 ID 与曲目。修复后上游详情、本站接口与浏览器均得到正确的 82 首；另一个歌单仍为 3 首，歌曲元数据与封面齐全。
- Chromium 已真实解码并播放 MP3：`readyState=4`，时间推进超过 1.5 秒，暂停/继续有效，封面加载成功。重启预览进程与浏览器刷新后账号仍保持连接；页面逐个打开两份真实歌单，渲染数量分别为 3/3 与 82/82，最终浏览器错误为 0。
- 收藏网易云、断开账号等有写入效果的行为在替身接口中验证；真实账号回归只在用户授权后执行相应动作。

全量 `npm run lint`、生产构建（包含 TypeScript）和 `git diff --check` 均通过。验证范围为 Chromium；尚未进行 Safari / iOS 真机验证。真实测试结束后已删除隔离测试用户及其级联登录记录和本地登录文件，仅保留脱敏日志与界面截图（本地 `.data/music-review/evidence/`，不提交到 Git）。
