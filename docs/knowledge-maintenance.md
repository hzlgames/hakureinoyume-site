# 知识维护规则

这个仓库后续主要由 agent 维护。知识库的目标不是记录所有实现细节，而是让下一次维护能快速理解当前架构、功能边界、部署约束和关键决策。

## 必须检查知识库的时机

- 准备执行 Git 远端同步前，包括 `git push`、创建 PR、更新 PR，或用户明确要求同步远端。
- 用户提醒更新项目文档、知识库、skill、架构说明或维护说明时。
- 已完成会影响架构、功能、API、部署、环境变量、公共组件、主题系统或资源路径的变更，并准备同步到远端时。

## 不强制更新的情况

- 只做本地探索、临时实验或未准备同步远端的改动。
- 只修正文案、样式细节或局部 bug，且不改变文档中描述的架构、功能边界、接口、部署和约束。
- 已检查过相关文档并能明确说明“无需更新”的情况。

## 变更到文档的映射

- 新增或改动路由：更新 `docs/architecture/current-architecture.md` 的路由说明，并按需更新 `docs/features/feature-overview.md`。
- 新增或改动 API：更新架构文档的接口说明；若影响认证、数据库、存储或兼容性，补 ADR。
- 修改后台认证、Better Auth、Prisma schema、cookie、角色或权限：更新认证架构、运维和 ADR。
- 修改背景图、主题变量、公共 UI 或素材路径：更新功能文档；涉及长期策略时补 ADR。
- 修改 Caddy、systemd、环境变量、数据库迁移、构建或部署命令：更新运维文档；改变部署策略时补 ADR。
- 修改 skill 触发条件或流程：更新 `skills/hakureinoyume-maintenance/SKILL.md` 和本文件。

## 远端同步前检查清单

1. 查看本次变更范围。
2. 判断是否影响文档中已有事实。
3. 更新对应文档，或记录无需更新的理由。
4. 长期决策变化时新增或修订 ADR。
5. 如果 skill 文件变更，运行 skill 校验。
6. 再继续远端同步。

## 写作要求

- 文档写当前事实，不写过期计划。
- 优先短句和清单，方便 agent 扫描。
- 不复制大段源码；描述行为、入口、约束和维护注意事项。
- 发现文档和源码冲突时，以源码为准，并立即修正文档。
